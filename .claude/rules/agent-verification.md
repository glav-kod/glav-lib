# Обязательные проверки перед завершением работы

Это единственный источник требований к проверкам для агентских режимов. Все режимы
(`/do`, `/master` и субагент `executor`) берут список проверок отсюда, а не хранят
собственные копии.

## Кто выполняет проверки

Проверки выполняет тот агент, который менял код.

- В режиме `/do` агент пишет код сам и сам же прогоняет проверки.
- В режиме `/master` код пишет субагент-исполнитель — проверки выполняет он.
  Мастер их не перепрогоняет: он требует от исполнителя фактический результат и
  запускает команду сам только тогда, когда в отчёте результата нет или отчёт
  противоречив.

## Какие проверки запускать

Проверку выбирай по затронутой части репозитория:

- менялся любой C#-код — `dotnet build GlavLib.sln -c Debug`. В `Directory.Build.props`
  включён `TreatWarningsAsErrors`, поэтому сборка падает и от предупреждения: чинить его
  нужно так же, как ошибку;
- менялся `GlavLib.SourceGenerators/` — обязательно
  `dotnet test GlavLib.SourceGenerators.Tests/GlavLib.SourceGenerators.Tests.csproj`.
  Тесты генераторов базы не требуют и должны быть зелёными целиком (27 тестов);
- менялись `GlavLib.Basics/`, `GlavLib.Abstractions/` или `GlavLib.Db/` — прогони
  `dotnet test GlavLib.Tests/GlavLib.Tests.csproj --filter 'FullyQualifiedName!~GlavLib.Tests.Db'`.
  Фильтр отбрасывает тесты, которым нужен Postgres, и оставляет 27 тестов, работающих
  без базы;
- менялись `GlavLib.App/` или `Sandbox/` — сборка обязательна, а
  `dotnet test Sandbox/GlavLib.Sandbox.API.Tests/GlavLib.Sandbox.API.Tests.csproj`
  запускай, только если база доступна: единственный тест проекта создаёт пользователя
  в `glavdb`;
- менялись миграции в `migrations/` — накатить их без Postgres нельзя. Проверь файл глазами
  по правилу `liquibase-migrations.md` и прямо скажи в отчёте, что накат не проверялся;
- затронуто несколько частей — прогони проверки каждой из них.

Тестовые проекты запускай **по отдельности**, а не через `dotnet test GlavLib.sln`: решение
целиком тянет за собой и те тесты, которым нужна база, и один общий прогон превращается
в набор падений, среди которых не видно собственных.

Если проверка падает — исправляй, пока не станет зелёной. Об успехе не сообщай, пока
проверка не прошла.

## Как отчитываться о проверках

Отчитывайся фактом, а не словом: назови запущенную команду и её результат. Формулировка
вида «проверил, всё хорошо» без названия команды отчётом о проверке не считается.

Если изменения вообще не затрагивают код репозитория (правки документации или инструкций
для агентов), скажи об этом прямо, вместо того чтобы запускать сборку впустую.

## Ограничения облачной среды

В облачной среде Claude Code нет Docker и Postgres, а `docker-compose.yml` поднимает пару
«мастер — реплика», поэтому недоступны ни `up.ps1`, ни `migrate.ps1`, ни тесты, работающие
с базой. Это `GlavLib.Tests.Db.DbSessionFactoryTests` и весь `GlavLib.Sandbox.API.Tests`.
Проверку, которая требует базы, за пройденную не выдавай — прямо скажи, что осталось
непроверенным.

.NET SDK в облачном контейнере ставит SessionStart-хук `.claude/hooks/session-start.sh`.
Хук асинхронный, поэтому в новом контейнере первые минуты `dotnet` может быть ещё не готов:
если команда его не находит, подожди или запусти хук вручную —
`CLAUDE_CODE_REMOTE=true ./.claude/hooks/session-start.sh`.

## Известные падения на `main`

В `GlavLib.Tests` два теста падают и без каких-либо правок:
`MultiLangMessageTests.It_should_format_message` и
`MultiLangMessageTests.It_should_ignore_argument_if_it_is_absent`. Причина в расхождении
шаблона и разбора: `MultiLangMessage.Format` подставляет аргументы по шаблону `{arg:type}`,
а тесты написаны на плейсхолдеры вида `{message}` — без типа. Падение к твоей правке
отношения не имеет; чинить его попутно не нужно, но и выдавать прогон за зелёный нельзя —
скажи, что упали ровно эти два теста и что они падали до правки.
