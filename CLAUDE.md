# CLAUDE.md — GlavLib

`GlavLib` — внутренняя библиотека GlavKod для .NET-приложений (.NET 10). Она даёт типы-значения
и сериализацию, многоязычные сообщения, работу с PostgreSQL и SQLite через NHibernate и Dapper, каркас
HTTP-команд на minimal API и source-генераторы, которые выпускают шаблонный код за разработчика.
Сборки публикуются пакетами NuGet, поэтому публичный API библиотеки — контракт с приложениями,
которых в этом репозитории нет.

## Язык общения, PR и коммитов

Общайся с пользователем **только на русском**. Это же требование обязательно для GitHub: заголовок
и описание PR, сообщения коммитов, комментарии в PR и ответы на замечания ревью пиши **на русском
языке**. PR или коммит на английском недопустим. Технические идентификаторы (имена файлов, классов,
методов, команд, таблиц) оставляй на языке оригинала в бэктиках. Подробные правила —
`.claude/rules/language-russian.md` и `.claude/rules/git-workflow.md`.

## Как ведётся работа над задачей

Работа идёт навыками из `.claude/skills/` — это набор `mattpocock/skills`, зафиксированный
в `skills-lock.json`. Основной путь от замысла до кода:

1. **`/grill-with-docs`** — интервью, затачивающее замысел; оседает в `CONTEXT.md` и `docs/adr/`.
2. **`/to-spec`** — синтез спецификации из разговора и публикация её issue в трекер.
3. **`/to-tickets`** — нарезка спецификации на вертикальные срезы с блокирующими рёбрами, по issue на срез.
4. **`/clear`** — контекст обнуляется, замысел остаётся в трекере.
5. **`/implement`** — реализация одного тикета в свежем контексте, с `/code-review` перед коммитом.

Точки входа мимо начала: **`/triage`** — для прилетевших извне баг-репортов и запросов,
**`/wayfinder`** — для работы, которая не умещается даже в планирование одной сессии,
**`/diagnosing-bugs`** — для трудных багов. Полное описание потока, ответвлений и границ
фаз — в навыке **`/ask-matt`**; здесь оглавление, а не пересказ.

Мелкую правку, которую проще объяснить словами, чем заводить под неё тикет, `/implement`
принимает описанием задачи — issue ради опечатки заводить не нужно. Прежних команд `/do`
и `/master` и субагента `executor` в репозитории больше нет: их работу делают `/implement`
и `/grill-with-docs`.

Спецификацию целиком, со всеми нарезанными по ней тикетами, реализует **`/implement-spec`**:
он ведёт тикеты по графу блокирующих рёбер, раздаёт готовые к работе подагентам в отдельных
worktree и сводит результат в одну ветку с одним pull request'ом на всю спецификацию.
`/implement` при этом остаётся способом взять в свежем контексте один тикет.

Довести работу до pull request'а — команда **`/pr`** (`.claude/commands/pr.md`). Её зовёт
человек, когда считает ветку готовой: сколько срезов в неё легло и закончены ли они,
знает он, а не агент. Исключение — `/implement-spec`: границы работы ему заданы самой
спецификацией, поэтому pull request он заводит сам, черновиком в начале, и снимает с него
черновой статус, когда закрыты все тикеты.

Разобрать законченную сессию — команда **`/retro`**: навык читает её журнал и предлагает,
что поправить в окружении агента, чтобы следующие запуски шли легче — навигационные
указатели, автоматические проверки, правила для ревью, доступ к нужной информации.
Зовёт его человек, код навык не меняет: он только приносит список предложений.

### Переопределения для навыков

Навыки пакета вендоренные, про GlavLib не знают ничего и правке не подлежат. В четырёх
местах их инструкции расходятся с этим репозиторием — здесь верно то, что написано ниже.

- **Тесты.** Оба навыка велят один раз в конце прогнать полный набор тестов. В GlavLib так
  делать нельзя: часть тестов (`GlavLib.Tests.Db`, весь `GlavLib.Sandbox.API.Tests`) требует
  поднятого Postgres, которого в облачной среде нет. Прогоняй нужные тестовые проекты
  **по одному, отдельными командами** — список и обоснование в `.claude/rules/agent-verification.md`.
- **Язык.** Навыки написаны по-английски. Общение, сообщения коммитов, issue, pull request'ы
  и комментарии — на **русском**, по `.claude/rules/language-russian.md`.
- **Стандарты кода.** `/code-review` и `/retro` называют файлы `CODING_STANDARDS.md`,
  `CONTRIBUTING.md` и `AGENTS.md` — в GlavLib таких файлов нет. Соглашения по коду лежат
  в `.claude/rules/` (`csharp-conventions.md`, `csharp-logging.md`, `nhibernate-models.md`,
  `sql-queries.md`, `code-comments.md` и остальные), а оглавление — в `CLAUDE.md`.
- **Сведение веток.** `/implement-spec` велит сводить работу подагентов в ветку pull request'а
  («merge its work to the PR branch»), не называя стратегию. В GlavLib это делается
  перебазированием и перемоткой (`git rebase`, затем `git merge --ff-only`): история
  репозитория линейная, merge-коммитов в ней не бывает. Порядок и запрещённые команды —
  в `.claude/rules/git-workflow.md`, раздел «Сведение работы в рабочую ветку».

## Сборка, тесты, окружение

Локальное окружение — `docker-compose.yml` (PostgreSQL 18, мастер и потоковая реплика, база
`glavdb`) и PowerShell-скрипты `up.ps1`, `migrate.ps1`, `rollback.ps1`, `stop.ps1`, `down.ps1`.
На macOS адреса реплик предварительно навешиваются на loopback скриптом `iface-setup.sh`.
В облачной среде Claude Code нет ни Docker, ни Postgres, поэтому запуск приложения
и тесты, работающие с базой, там недоступны — доступны только сборка и тесты без базы.

- **Сборка:** `dotnet build GlavLib.sln -c Debug`. В `Directory.Build.props` включён
  `TreatWarningsAsErrors`, поэтому сборка падает и от предупреждения. В облачной среде SDK ставит
  SessionStart-хук `.claude/hooks/session-start.sh` — он же восстанавливает пакеты решения. Хук
  асинхронный, поэтому в новом контейнере первые минуты `dotnet` может быть ещё не готов: если
  команда его не находит, подожди или запусти хук вручную —
  `CLAUDE_CODE_REMOTE=true ./.claude/hooks/session-start.sh`.
  Ручной запуск ставит SDK, но `PATH` сессии не меняет: хук правит окружение только через
  `CLAUDE_ENV_FILE`, а её задаёт харнесс при своём вызове. После ручного запуска вызывай
  компилятор по полному пути — `/root/.dotnet/dotnet` — либо добавь этот каталог
  в `PATH` сам.
- **Тесты генераторов:** `dotnet test GlavLib.SourceGenerators.Tests/GlavLib.SourceGenerators.Tests.csproj` —
  базы не требуют, должны быть зелёными целиком (27 тестов).
- **Тесты библиотеки без базы:**
  `dotnet test GlavLib.Tests/GlavLib.Tests.csproj --filter 'FullyQualifiedName!~GlavLib.Tests.Db'` —
  39 тестов, должны быть зелёными целиком.
- **Тесты SQLite:** входят в набор выше (`GlavLib.Tests.Sqlite`) и Postgres не требуют —
  SQLite работает с временным файлом, поэтому они зелены и в облачной среде.
- **Тесты, которым нужна база:** `GlavLib.Tests.Db.DbSessionFactoryTests`,
  `GlavLib.Tests.Db.NpgsqlUserTypesTests` и весь
  `Sandbox/GlavLib.Sandbox.API.Tests` — запускаются только при поднятом Postgres.
- Тестовые проекты запускай **по отдельности**, а не через `dotnet test GlavLib.sln`: иначе
  в один прогон попадают тесты, требующие базы, и собственные падения теряются среди чужих.
- **Публикация пакетов** — GitHub Actions, workflow `.github/workflows/publish.yml`: он
  собирает решение, упаковывает пакеты, публикует их в nuget.org и создаёт релиз GitHub,
  к которому те же `.nupkg` прикладываются файлами. Работу делают скрипты каталога `ci/`,
  поэтому выпуск воспроизводится и локально. Версию считает `ci/version.sh` из даты,
  номера сборки и ветки, руками её не проставляют; она же даёт тег релиза вида `v<версия>`.
  Публикация идёт через trusted publishing: постоянного ключа в секретах нет, шаг
  `NuGet/login` меняет OIDC-токен задания на ключ, живущий час. Релизу внешние секреты
  не нужны — хватает `GITHUB_TOKEN` задания с правом `contents: write`.
  Версия .NET SDK задана в workflow явно, потому что компилятор старее
  Roslyn из `Microsoft.CodeAnalysis.CSharp` не загружает наш source-генератор (ошибка CS9057).
  Подробности — в `project-map.md`. Проверок на pull request workflow не запускает: выпуск —
  единственное, чем он занят.

## Зависимости между сборками

`GlavLib.Abstractions` не тянет внешних зависимостей, `GlavLib.Basics` не знает про ASP.NET,
`GlavLib.Db` — про HTTP. Границы содержательные: правка, которая их нарушает, почти всегда
решается иначе. Полная картина — в `.claude/rules/project-map.md`.
