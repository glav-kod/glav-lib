# Политика обновления документации

## Обновляй документацию только при изменении

- архитектурного решения;
- бизнес-правила;
- workflow (процесса, порядка шагов);
- публичного контракта (API, интерфейс, схема БД);
- способа расширения системы (паттерн, точка расширения);
- требований к тестированию;
- рекомендаций для будущих разработчиков и AI-агентов.

## Не обновляй документацию при

- рефакторинге;
- переименовании (без изменения смысла);
- исправлении багов без изменения поведения;
- внутренних оптимизациях;
- изменении реализации без изменения публичного контракта.

## Какие документы проверять на устаревание

Когда правка подпадает под критерии выше, проверь, не стал ли неверным текст в:

- `CLAUDE.md`;
- файлах `.claude/rules/`, в первую очередь в `project-map.md` и `persistence.md`;
- XML-комментариях к публичным типам и методам, если правка меняет их поведение или контракт.

Отдельного `README.md` в репозитории нет: устройство проекта описано в `CLAUDE.md`
и `.claude/rules/project-map.md`. Если README появится, проверяй и его.

Публичный API библиотеки — тоже документация для потребителя. Изменив сигнатуру, поведение
или состав публичного типа, приведи в соответствие описания в `project-map.md`, а не только код.

## Куда какой текст писать

Документация разнесена по назначению, и место определяется тем, на какой вопрос текст
отвечает, а не тем, какой файл открыт:

| Вопрос | Место |
|---|---|
| Где что лежит | `.claude/rules/project-map.md` |
| Как это работает | сам код — пересказов его механики в репозитории нет |
| Почему решено именно так | `docs/adr/` |
| Как это называется в проекте | `CONTEXT.md` в корне |

`project-map.md` загружен в контекст каждой сессии, поэтому объяснения механики в него
не дописывают: строка в таблицу — да, абзац — нет. Если по итогам правки объяснять нужно
больше, чем строку, то это либо описание механики — его место в самом коде, — либо решение
с обоснованием, и тогда оно уходит в `docs/adr/`. Карту поправь только там, где изменилась
раскладка файлов.

## Когда правится документация

Документация описывает текущее устройство проекта, поэтому она правится тем же изменением,
что и код, а не откладывается отдельной задачей.

Если обновлять нечего, скажи это прямо, вместо того чтобы дописывать в документацию
пересказ внесённых изменений.
