# Язык общения и PR

Всегда общайся с пользователем на **русском языке**: объяснения, вопросы, комментарии в ответах.

Код, идентификаторы, команды и технические термины оставляй на языке оригинала (английский, SQL и т.д.).

## GitHub Pull Requests

GitHub PR создавай и обновляй на **русском языке**:
- заголовок PR;
- описание PR;
- секции вроде Summary / Validation / Testing (названия секций можно оставить на английском, если это шаблон репозитория, но содержимое пиши по-русски).

Это же требование действует для сообщений коммитов, комментариев в PR и ответов на замечания ревью.

## Понятность важнее краткости

Русский язык здесь — необходимое, но не достаточное условие: текст должен быть ещё и понятным.

- Пиши полными предложениями, а не обрывками и не машинным телеграфным стилем.
- Не используй кальки с английского там, где есть обычное русское слово
  («засабмитить» → «отправить», «задеплоить» → «выкатить», «аппрувнуть» → «согласовать»).
  Устоявшиеся технические термины (`merge`, `rebase`, pull request, миграция, source-генератор)
  переводить не нужно.
- Не переводи имена файлов, классов, методов, команд, пакетов и таблиц — оставляй как есть
  в бэктиках.
- Формулировки для коммитов и pull request'ов подробно описаны
  в `.claude/rules/git-workflow.md` (раздел «Понятный язык в коммитах и PR»).
